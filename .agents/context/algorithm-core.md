# SmartPI regulation core and classic learning loops

Scope: the regulation law and the model learning of `custom_components/vtherm_smartpi` (`SmartPI` in `algo.py`, parts in `smartpi/`). Out of scope: `smartpi/room_model/` and `smartpi/tar_learning/` (always enabled by the handler). Paths below: `smartpi/` = `custom_components/vtherm_smartpi/smartpi/`. Constants live in `smartpi/const.py`. "live" = the `live` attribute of the diagnostic sensor (`smartpi/diagnostics.py::build_published_diagnostics`).

There is no integral-guard module and no reference governor. Anti-windup is conditional integration plus back-calculation (section 2). The published `live` tree has no such sections.

## 0. Tick pipeline (`algo.py::SmartPI.calculate`)

Order of one tick (the scheduler also calls it on a 60 s heartbeat, `SMARTPI_RECALC_INTERVAL_SEC`):
1. HVAC-mode transition HEAT<->COOL: PI reset; the mode-dependent model is kept per mode (see Invariants, Signs); a persisted model with an inconsistent `a` sign resets only the `a` channel.
2. Validation/OFF (`_validate_and_handle_off`), guard cut (section 9), `tint_filter` (adaptive low-pass; feeds dead-time detection and learning anchors only, never the PI).
3. `_update_time_tracking` (dt capped at one cycle), `_manage_setpoint` (error_i raw, error_p shaped).
4. Dead-time estimator update, learning update (measurement pulses: advanced at step 3, commanded through the on/off path of step 5).
5. Bootstrap phase = hysteresis bang-bang (`command_is_on_off`), returns early (section 6).
6. Deadband/near-band, governance regime, gains + FF, `ctl.compute_pwm`, `ctl.track_output_limit`, rate limit, timing constraint, publish candidate output.
The scheduler (VT) later reports the power really applied (receipt or cycle start); only the committed power feeds learning (`_committed_on_percent`).

## 1. Physical model (`smartpi/ab_estimator.py`)

- 1R1C, per minute: `dT/dt = a*u - b*(Tin - Tout)`; `u` in [0,1] is the active power demand (cooling power in COOL).
- Mono-mode, signed `a`: HEAT `a > 0`, COOL `a < 0`; `b > 0` in both. `ABEstimator._mode_sign` is +1 (HEAT) / -1 (COOL). `a` clamped to |a| in [1e-5, 0.5], `b` in [1e-5, 0.05] (`A_MIN/A_MAX/B_MIN/B_MAX`). Initial `a=5e-4`, `b=1e-3` (neutral start).
- `tau = 1/b` minutes (room time constant). `b` is learned from passive (OFF) windows, `a` from active windows. Static gain `b/a` = power per degree of (setpoint - outdoor) at equilibrium.
- Error signs: `error = SP - Tin` in HEAT, `Tin - SP` in COOL (`_manage_setpoint`), so a positive error always means "demand more power". Everything downstream (PI, anticipation, deadband) is mode-agnostic on that signed error.
- Dead-time naming is by response direction, not by mode: `deadtime_heat_*` = rising-temperature response, `deadtime_cool_*` = falling-temperature response. Only the active response is measured (after a start: heat in HEAT, cool in COOL, `DeadTimeEstimator.active_deadtime`, `active_slot`); the other slot stays empty, and a saved dead time after a stop is dropped at load (also in the mode stash). The pre-start trend window starts one model emitter lag (theta + tau_e) after the last stop (active dead time without a model).
- Persisted (`est_state`): `a`, `b`, `model_hvac_mode`, counters, `a_meas_hist`/`b_meas_hist`, `a_hat_hist`/`b_hat_hist`, drift channels. Live: `live.model.{a,b,tau_min,tau_reliable,confidence,a_stability_ratio,b_stability_ratio,deadtime_*}`.
- `tau_reliability()` (-> `tau_reliable`, `tau_min`): needs `learn_ok_count_b >= 5`, >= 5 values in the `b_hat` history, MAD(b)/median(b) <= `B_STABILITY_MAD_RATIO_MAX` (0.60), median b inside bounds. Gains, near-band, deadband, FF1 all require it.

## 2. PI controller (`smartpi/controller.py::SmartPIController`)

- Output: `u_cmd = clamp(u_ff + Kp*e_p_db + Ki*I, 0, 1)`; `I` integrates the error on the anticipated temperature (`error_i_ctl`, section 4) in degC*min; `e_p` is the P error on the anticipated temperature after the deadband projection. Units: Kp 1/degC, Ki 1/(degC*min). `|I| <= 2/Ki` (`i_max`).
- Integral modes (`ctl.last_i_mode`, `live.temperature.integral_mode`):
  - `I:RUN` normal; `I:UNWIND(SAT_HI|SAT_LO)` saturated but integral may only move toward zero when within `NEAR_SETPOINT_UNWIND_STEPS` (1.5) sensor steps of the setpoint and saturation comes from P alone; `I:SKIP(SAT_*)` conditional integration blocked (saturated against the error); `I:CLAMP(near_ovr)` no growth once `error <= OVERSHOOT_I_CLAMP_EPS_C` (0.04).
  - `I:FREEZE(deadband)` core deadband; `I:HOLD` / `I:HOLD(<mode>)` external or generic hold (sources: `live.temperature.integral_hold_source`, listed in `diagnostics.md`); `I:FREEZE(hvac_off|missing_sensor)`, `I:OVERRIDE(guard_cut)`, `I:RESET(...)`.
- Anti-windup, two layers:
  1. Conditional integration against the static limit `u_max` (`max_on_percent` in linear space; 1.0 otherwise).
  2. `track_output_limit` (per tick): back-calculation of the excess over `u_max` with `Tt = Ti = Kp/Ki`, integral moves toward zero only, never across (`_back_calculate`). Only in modes `I:RUN/SKIP/CLAMP`. Rate limit and min-activation timing are NOT saturations and never drain the integral. Published `live.analysis.control.aw_du`.
- Rate limit (`SmartPI._apply_soft_constraints`): `MAX_STEP_PER_MINUTE` 0.25/min on `u_cmd`; boost rate `SETPOINT_BOOST_RATE` 0.50/min when the boost is active; bypassed on first output, setpoint change, dt<=0. Min-activation delay (`update_timing_constraints`) zeroes a too-short ON request (switch outputs only; `live.analysis.control.forced_by_timing`).
- Bumpless transfers on the integral: Ki change rescales `I` by `old_Ki/new_Ki` (`ctl.transfer_gains`, called by `_apply_gains_and_ff`); a step of the static holding power is absorbed by `ctl.absorb_feedforward_step` (`I <- I - dFF/Ki`, may cross zero); deadband entry is NOT bumpless (integral frozen as is).
- Deadband (`smartpi/deadband.py::DeadbandManager`, `smartpi/deadband_output.py`): configured `deadband_c` (default `DEFAULT_DEADBAND_C` 0.05 degC), enter at `|e| < db`, exit at `|e| > db + DEADBAND_HYSTERESIS` (0.025); inactive while `tau` unreliable. Core deadband (`|e| < db`) freezes the integral; the shell (in deadband but not core) holds it. In the deadband the output is the structural hold `u_ff1 + Ki*I` and P is projected: `deadband_frozen` (no P), or with `deadband_allow_p` a damped P edge (`deadband_edge` needs `DEADBAND_EDGE_PERSISTENCE` = 2 same-sign samples). Published `live.feedforward.{deadband_power_source,deadband_p_mode}`.
- Near-band: asymmetric thresholds. HEAT with a response model of the mode and `a>0`: `NB = db + slope*(L + cycle/2)`, L = effective dead time theta + tau_e/2 above the setpoint, emitter lag theta + tau_e below (3S/4 and S when the split is assumed; `update_near_band_auto`, below clamped to [db+0.1, 2.0], above <= below, factor `NEAR_BAND_ABOVE_FACTOR` 0.40 fallback); otherwise configured `near_band_deg` (default 0.40; COOL always configured; source `no response model` without a model). Hysteresis `NEAR_BAND_HYSTERESIS_C` 0.05. Source in `live.analysis.control.near_band_source`. Near-band decides gain taper, guards, governance regime.
- Hysteresis shell (bootstrap only, `calculate_hysteresis`): HEAT ON at `SP - HYST_LOWER_C`, OFF at `SP + HYST_UPPER_C` (user options `CONF_SMART_PI_HYSTERESIS_ON`/`_OFF`, defaults 0.3 and 0.5 C); COOL mirrored. In band the previous on/off state is kept (`live.control.hysteresis_state`).
- Persisted: only `ctl_state.integral`. Inactivity reset: active wall time older than `PROLONGED_PAUSE_MEMORY_EXPIRATION_MIN` (5760 min = 96 h) resets the controller and the holding-power transfer state on the next active tick; learned model is kept.

## 3. Gains (`smartpi/gains.py::GainScheduler`)

- Needs tau reliable, `a` of the right sign (|a| > 1e-6), a delay `L` > 1 s. Otherwise safe gains `KP_SAFE` 0.55 / `KI_SAFE` 0.010 (source `safe`).
- Rule (IMC/SIMC): `L` in min (below); `lambda = max(3*L (4*L in valve mode), 2*cycle_min, 5)`; `Kp = clamp(1/(|a|*(lambda+L)), KP_MIN 0.10, KP_MAX 5.0)`; `Ti = min(tau, 4*(lambda+L))` (`GAIN_TI_LAMBDA_FACTOR`); `Ki = clamp(Kp/Ti, KI_MIN 0.001, KI_MAX 0.050)`. Constants `GAIN_LAMBDA_*` in const.
- Near-band taper (deterministic in the error): `Kp *= 0.75 + 0.25*r`, `Ki *= 0.45 + 0.55*r`, `r = |e|/threshold` in [0,1] (`NEAR_BAND_TAPER_KP_MIN/KI_MIN`). Sources get a `_nearband` suffix.
- Governance gate (`gains` domain): HARD_FREEZE/FREEZE keep previous Kp/Ki (source `frozen`); SOFT_FREEZE_DOWN lets gains only decrease (`_softfreeze`).
- Persisted `gs_state`: kp, ki, sources. Live: `live.control.{kp,ki,ti_min}`, `live.analysis.governance.{kp_source,last_decision_gains,last_freeze_reason_gains}`.
- `L` (`gains.start_dead_time`): reliable active dead time after a start of the mode, source `dead time`; none: safe gains. Pre-model gains too; published `analysis.control.gain_*`. Not the response model (lot b4 rejected).

## 4. Setpoint handling and anticipation (`smartpi/anticipation.py`, `smartpi/setpoint.py`)

- One reference: the regulation always works on the raw setpoint (no shaped setpoint, no setpoint filter option). `error` (`live.temperature.error`, deadband, guards, FF, learning) is on the measured temperature.
- Anticipation (`correction_c`): P and I errors read `Tin + c`, `c = clamp(slope * horizon, +/-ANTICIPATION_MAX_C) * w`. `slope` = least-squares slope of the raw `dt_est.tin_history` plus the current tick over the last `min(max(ANTICIPATION_MIN_WINDOW_S, horizon), ANTICIPATION_MAX_WINDOW_S)` (= horizon, 600-1800 s); 0 with < 3 samples or a span < half the window. Fade `w = clamp(2 - e/c, 0, 1)`, `e` = raw target - Tin: 0 when the room approaches the setpoint from farther than 2c, 1 within c of it, beyond it or when moving away. Only while the command is not on/off (0 in bootstrap hysteresis and during a measurement pulse, of the start or of a calibration). Deadband gate (`DeadbandGate.apply`, state on `SmartPI._anticipation`, not persisted, reset with the controller and on a mode change): outside the deadband `c` passes unchanged; while `deadband_mgr.in_deadband` is true (the state left by the previous calculation) `c` is kept until it is 0 or of the sign opposite to the previous calculation's, then it is 0 until the room leaves the deadband. Why: no `Kp * c` step at the entry, no swing from a quick sensor move once settled. Same rule in HEAT and COOL (`anticipated_error` adds `c` to the measured temperature: lowers the HEAT error, raises the COOL one).
- Horizon (`select_horizon`, `SmartPI.anticipation_horizon`), HEAT and COOL: emitter lag theta + tau_e of the mode's response model (`learn_win.model`; S when assumed; source `response model`); without a model the pulse-kept lag (`measurement pulses`), else the active dead time, reliable and positive only (`dead time`); else 0 (`none`). Live: `live.analysis.control.{anticipation_c,anticipation_horizon_s,anticipation_horizon_source}`.
- A setpoint step has no braking stage: the room rising fast toward the new setpoint raises `c` and the fade lets the P and I errors fall as it nears.
- Boost (`update_boost_state`): setpoint step >= `SETPOINT_BOOST_THRESHOLD` (0.3) arms the 0.50/min rate limit; ends when `|error| < SETPOINT_BOOST_ERROR_MIN` (0.3). `live.setpoint.boost_active`.
- Setpoint change (`calculate`): change > 0.01 degC clears governance cycle regimes and the resume hold, forces the rate-limit bypass, invalidates the running learning window and blocks ON/A learning for the transient. Change >= `SETPOINT_MODE_DELTA_C` (0.5) additionally restarts the error history (`_e_filt`); the integral is always preserved.
- Error filter `_e_filt` (`ERROR_FILTER_TAU` 25 min) drives near-band detection only.

## 5. A/B learning (classic loop)

Pipeline: `LearningWindowManager.update` -> window -> `ABEstimator.learn` -> robust publication. Learning runs only when `learning_enabled` and governance allows (a calibration has no exemption). Heartbeat ticks feed it (dt capped to one cycle).

- Window (`smartpi/learning_window.py`): multi-cycle accumulation of Tin, Tout, power (Welford CV, energy integral). Passive window (b) when mean power `< U_OFF_MAX` (0.05); active (a) when `> U_ON_MIN` (0.20); in between `skip: low excitation`. Slope = OLS on RAW temperatures (`ABEstimator.robust_dTdt_per_min`: >= 6 samples, `OLS_MIN_JUMPS` 3 level changes, fitted span >= `OLS_MIN_SPAN_STEPS` 1.5 sensor steps, t-stat >= `OLS_T_MIN` 2.5). Window extends until a robust slope or `DT_MAX_MIN` (240 min) timeout. Power CV > `U_CV_MAX` (0.30) closes it (early submit only if a slope is already valid). `|slope| > 0.35 degC/min` rejected.
- Start gates (`power_steps.py`, wait `response_model.settle_s`): `a` at step + S (cap `AB_SETTLE_ACTIVE_CAP_FRAC` x median episode), `b` at cut + S (any split); no model: no wait. `b` = (a p - slope)/dT, p delivered, usable `a` (else p = 0); `b` obs replayed on an `a` change and vice versa, once (> `AB_VAL_TOLERANCE`, never chained). `a` windows before 5 b samples kept, replayed when b publishes. Learning stage: no window before the model (provisional ok). A power start ends a passive window. `LEARNING_PAUSE_RESUME_MIN` (20 min) after OFF/resume; one cycle after reboot.
- Acceptance gates (reason in `learn_last_reason`, `live.learning.last_reason`):
  - b: `|Tin-Tout| >= DELTA_MIN_OFF` 0.5, `b_meas > 0`; HEAT needs initial `Tin-Tout >= AB_B_MIN_PASSIVE_GRADIENT_C` (2.0) and outdoor <= target - `AB_B_OUTDOOR_TARGET_MARGIN_C` (2.0); COOL mirrored.
  - a: `|delta| >= DELTA_MIN_ON` 0.2; needs >= `AB_A_SOFT_GATE_MIN_B` (5) b measurements; `a_meas = (dTdt + b*delta)/u` must have the mode sign; `u` is the delivered power (applied power filtered by the emitter lag) when the emitter lag is known.
  - Governance thermal domain, setpoint transients and guard-cut skipped.
- Robust aggregation (`smartpi/ab_aggregator.py`, `ab_estimator.py`): history of `AB_HISTORY_SIZE` 31 measurements per channel; published value = weighted median (newest `AB_WMED_PLATEAU_N` 11 weight 1, geometric tail `AB_WMED_R` 0.85) ; plain median if <= 11 points. First publication needs `AB_MIN_SAMPLES_A/B` 5 (a may publish from 4 when MAD <= 10 % of median, `AB_MIN_SAMPLES_A_CONSISTENT`); a collection is held until the delivered power model is settled (`LearningWindowManager.a_model_ready`: mode's model published, or 4 heating phases without, `RESPONSE_LAG_RESOLVE_EPISODES`). Outlier gate: |x - center| <= `AB_MAD_SIGMA_MULT`(3) * 1.4826 * MAD, MAD floored by `AB_DRIFT_MAD_FLOOR_ABS` and by `AB_MAD_REL_FLOOR` (2 % of the median); the drift detection and the recentering read the same floored MAD. A change of `b` replays stored `a` measurements.
- Drift/recentering (`smartpi/ab_drift.py`): rejected candidates fill a buffer (8); >= 6 consistent same-side, sequence gaps <= 3, tight, shifted >= 3 MAD -> state `DRIFT_SUSPECTED` then `RECENTERING` for up to 5 accepted cycles with a bounded virtual gate center (alpha 0.25). `a` drift is only allowed once `b_converged_for_a()` (11 b updates, MAD ratio <= 0.30, last-5 range <= 10 %). Live: `live.learning.{a_drift_state,b_drift_state}`.
- Integral balance pools (`smartpi/ab_window_balance.py`): windows closed without a robust slope contribute segments `T(t2)-T(t1) = a*U - b*D` between raw sensor steps; segments (>= 15 min, monotone, <= 12, <= 24 h old) pooled per parameter and submitted once the quantisation-bounded relative uncertainty <= `AB_BALANCE_MAX_REL_UNC` (0.25). Sensor step estimate = `balance.resolution_c` (floor 0.05). Live: `live.analysis.learning.balance_pool`.
- Outcomes (`smartpi/learning_outcomes.py`): normalised reason counts over 24 h per parameter -> `live.analysis.learning.window_outcomes_24h`.
- Confidence (`smartpi/ff_ab_confidence.py::ABConfidence`): `ab_ok` = tau reliable and both `learn_ok_count >= AB_CONFIDENCE_MIN_SAMPLES_*` (11); `ab_degraded` = tau reliable, fewer samples; `ab_bad` = tau unreliable; `ab_bootstrap` while in bootstrap phase (published) / initial. Published as `live.model.confidence`. `live.learning.stage`: bootstrap / learning (<31 accepted) / monitoring / degraded.
- Learning block (`smartpi/learning_block.py`): service pause (persisted) OR disturbance OR heating-unavailable entity blocks every learning; the temperature history, episode starts and regulation stay; heating unavailable holds the integral, then over the dead time. `reset_learning` clears model, controller, dead times (guard counters kept). `live.learning.{enabled,block_reason}`.
- Governance (`smartpi/governance.py`, matrix `GOVERNANCE_MATRIX` in const): regime per tick = WARMUP (bootstrap) > DEGRADED (no outdoor) > PERTURBED (power shedding) > HOLD (integral hold) > SATURATED (u_cmd at 0/1) > DEAD_BAND > NEAR_BAND > EXCITED_STABLE. Thermal domain: HARD_FREEZE in DEAD_BAND/HOLD/PERTURBED/DEGRADED, adapt otherwise (also SATURATED, WARMUP). Gains domain: FREEZE in WARMUP/SATURATED, SOFT_FREEZE_DOWN in HOLD, HARD_FREEZE in DEAD_BAND/PERTURBED/DEGRADED. More than one regime in a cycle -> HARD_FREEZE `regime_transition`; learning-resume pause -> HARD_FREEZE `perturbed`. Live: `live.governance.*`.

## 6. Bootstrap phase, dead time, emitter lag

- Phase (`SmartPI.phase`, from `smartpi/learning_start.py::LearningStart.phase`): HYSTERESIS (the learning stage) until `>= 5` a and `>= 5` b measurements are collected (or `a` already usable, published or a starting value standing) and the delivered power model is resolved; else CALIBRATION while a pulse of a calibration commands the output; else STABLE. The stage and the source of the command are separate: `command_is_hysteresis` (stage and bootstrap start) and `command_is_on_off` (also a measurement pulse) decide what drives the command, learning, guards and dead-time updates. In HYSTERESIS the output is bang-bang (section 2), raw setpoint, no anticipation, full power, dead-time and learning run; guards inactive. Persisted state survives, so a restored model starts in STABLE. Live: `live.control.phase`, `live.learning.{bootstrap_status,bootstrap_progress_percent}` (`step1 - waiting response model`, `step2 - collecting emeas`).
- Dead time after a start (`smartpi/deadtime_estimator.py`): FSM on power transitions; start: power >= 0.80, >= 600 s since the last stop; a stop arms nothing. Detection: smoothed temperature departs from its trough/peak by >= 0.05 degC, look back to the inflection; `dt = inflection - start`. Timeout 4 h. Published value = median of last 6 detections (reliable from the first). `deadtime_trend.py` removes a free-running pre-start trend; a weak-evidence detection never shortens a published value (`ignored`/`rejected`/`detected` in `live.analysis.deadtime.*_last_outcome`). Persisted `dt_est_state`; stashed per mode. The gains read it; the integral holds only without a response model.
- Delivered power of `a` (`smartpi/power_steps.py::PowerSteps`, also episodes, heating phases): command delayed by theta, then first order tau_e (applied power without a model).
- Calibration (`smartpi/calibration.py`, held by `LearningStart`; request rules in its docstring): drives the measurement pulses in either start mode, own count (3, not counted for the learning stage), own limits (`pulse_limits`: rest S + `CALIBRATION_REST_EXTRA_S`, trough lead theta_eff, heat max 2(theta_eff + H), gap 2H; 0 without a model), on/off path (commit, then one `dt_est.update`). Its stop ends when the pulse's event has closed. Calibration events (source `calibration`) form their own reading set in `EventReader`; two agreeing readings give the published reading; at a `readings agree` end `a` is corrected when it differs from the value in force (`|a|`, `b`; the horizon in use is published as `in_force_lag_s`) by more than `CALIBRATION_CORRECT_REL` 30 % (`correct_a`, `StartingValues.correct`, credit latched; FF step via `HoldingTransfer.note_learned_step` into the integral; a Kp change is not moved into it, the P term acts on the error); `b` only with `CALIBRATION_CORRECT_B` (False). The emitter lag is corrected only by the response model's own calibration rule. End during a pulse: rest hands back, heat -> `stop_heating`, stop goes on; `advance` re-checks the end once the pulse ends; cancels are immediate. In progress: `est.calibrating` makes `learn` skip `a`. After each calibration pulse `recovering` holds the integral until demand <= 0 (not saved). Ends: `readings agree`, `pulses done`, `time limit` (48 h, also checked in a guard cut), `cancelled` (mode change, learning stage back, reset, pause). A stop ends the pulse (counts); the calibration goes on.

## 6b. Measurement events, readings and starting values

- Peak search (`smartpi/peak_search.py::PeakSearch`): `EVENT_PEAK_BIN_S` (300 s) bins from the cut; peak = earliest strictly highest bin mean (lowest in COOL), confirmed by a closed bin `EVENT_PEAK_CONFIRM_S` (1800 s) later, none after `EVENT_PEAK_MAX_S` (4 h); outcomes confirmed / cut short / none. The estimator's search (direct start) also confirms on a later closed bin >= max(0.05 C, 2 sensor steps (`sensor_step.py`), 0.5 x rise since the cut) under it, and on the bin in progress at the next heating.
- Detector (`smartpi/measure_event.py::MeasureEventDetector`, owned by `learn_win` (`events`); HEAT rest/phase saved as `lw_state.event_restart`): rest, phase of power above 1 %, cut (cuts shorter than `EVENT_PHASE_MIN_OFF_S` belong to the phase), peak search; HEAT and COOL. Each event carries its mode, the learning phase as `context` and a `source` read at the start of the phase: pulse, bootstrap (hysteresis drives), calibration, regulation. The reader reads those of source pulse, bootstrap or calibration (calibration ones as a separate set); the model reader reads all.
- Record (`MeasureRecord`): power, raw room temperature and outdoor temperature as change points, bounded (`RECORD_MAX_POINTS` 6000 per channel, trimmed to `RECORD_SPAN_S`, about 30.5 h); saved. For a switch the power channel holds the real on/off edges of each applied cycle (`note_cycle`, via `LearningStart.note_receipt`); a valve, or a scheduler without receipts, records the observed power (cycle fraction).
- Reader and fit (`smartpi/event_reading.py::EventReader`, `smartpi/event_fit.py`): a closed event opens a reading whose window starts `READING_LEAD_S` before the step and first ends at the close of the event; the fit (pure delay `D`, first-order lag, `a`, losses `b` on the applied power; emitter lag `L` = `D` + lag) runs as an executor job queued by the reader, applied at the next calculation; the window then grows to `READING_WINDOW_LAGS` lags, up to `READING_MAX_FITS` fits. Two complete readings of a blank start and of the same mode whose `a` and `L` each differ by at most `READING_AGREE_REL` of the larger (20 %) are kept for that mode (means; saved; dropped by a reset; one set per mode like the estimator's `a` channel). A stop, a mode change, the start of a calibration or a reset ends the readings in progress. numpy/scipy load lazily.
- Starting values (`smartpi/starting_values.py`, `ABEstimator.give_starting_values`, state in `est_state.starting_values`): the kept `a` of each mode is given once per mode and blank start, the mean `b` (shared by the modes) with the first hand-over only; they stand for the learning's own values and write no history or counter. `a` is released at the learning's first own publication, `b` when the learning's own time constant is reliable. Each value of the first hand-over earns `KEPT_RAMP_MEASURES` (5) of latched warm-up credit, a later hand-over of the other mode earns none. A HVAC mode change sets the standing `a` aside with its channel (mode stash) and brings it back with it, `b` stays; a learning reset drops all.
- Learning start (`smartpi/learning_start.py`, `SmartPI(learning_start="bootstrap"|"direct")`, user option `smart_pi_learning_start`, default bootstrap, passed by the handler). It acts on a blank start only: `configured` is the option, `mode` the start of the learning in progress. A loaded state with measurements, starting values, pulses or readings keeps its start (saved as `learning_start` for the direct start, no key = bootstrap); a blank state and a learning reset take the configured one and set `dt_est.direct`. Bootstrap: the hysteresis heating phases are events of source bootstrap read like pulses; kept values are given at the end of the learning stage; the kept lag is published only; the regulation is unchanged by the readings. Direct: PI from the first minute on the fallback gains, up to three pulses per mode (`smartpi/measure_pulse.py`, rules shared with the calibration: decisions.md), wanted while readings are pending or the mode has no response model; the kept values give the pre-model gains (`gains.py::pre_model_gains`, source `measurement_pulses`) and, without a response model, the anticipation horizon (source `measurement pulses`); the integral starts from zero when the stage ends. Summary: `live.learning.start` (`LearningStart.public()`).

## 7. Feed-forward (`smartpi/feedforward.py`)

One mechanism: the holding power `u_ff1`, clamped to [0,1]; runtime FF = `u_ff1` (also inside the deadband). Live: `live.analysis.feedforward.*` (`u_ff1`, `reason`; `u_ff_final` and `u_ff_effective` equal `u_ff1`), `live.power.ff_percent`.
- FF1 (`compute_ff`): `u_ff1 = clamp(k_ff*(SP_raw - Tout), 0, 1) * warmup_scale`, `k_ff = clamp(b/a, -3, 3)` signed (negative in COOL, so the product is positive when cooling is needed); `k_ff = 0` unless `a` and `b` are collected, tau reliable and `a` has the mode sign. No outdoor value -> FF1 is 0 (`ff_no_ext_temp`).
- Warmup: `warmup_scale = clamp(ramp_count/ff_warmup_ok_count) * clamp(cycles_since_reset/ff_warmup_cycles)`, defaults 30 and 6 (`SmartPI.__init__`); `ramp_count` = max(latched credit of the starting values, own accepted count) (section 6b), so the ramp never drops at a release. The cycle count is persisted (`cycles_since_reset`), so the restored integral and FF1 come back at their pre-restart level.
- Holding-power source (`SmartPI._select_holding_power`): a qualified published room model can replace FF1 (HEAT, PWM, `compute_room_ff`, full weight); source change steps are absorbed by the integral. Out of scope here. `live.feedforward.source`.
- Valve curve linearization (`smartpi/valve_curve.py`): opt-in for valve-driven emitters. The model, PI and learning work in linear demand space; `TwoSlopeValveCurve.apply/invert` map to and from valve position (defaults min 7 %, knee demand 80 % -> valve 15 %, max 100 %). `max_on_percent` is converted to linear space; applied valve positions (whole percents) are inverted before learning; timing constraints are skipped in valve mode; `lambda` uses the valve dead-time factor 4. `live.power.linear_*`, `live.valve.*`.

## 8. Commit and power plumbing

`ctl.u_cmd` -> rate limit -> `_on_percent` (candidate, linear) -> actuator command through the valve curve -> scheduler commits -> `_committed_on_percent` (`live.power.current_cycle_percent`, `next_cycle_percent`, `command_percent`, `limited_percent`, `applied_percent`). Learning and dead-time read the committed value only. `max_on_percent` caps the output and is the anti-windup limit.

## 9. Guards, safety and OFF behaviour

- Guard cut (overheat cut; `smartpi/guards.py`, evaluated in `handler.py`, applied in `calculate`): HEAT only. Triggers when `T > SP + near_band_above` while the device is active; releases at `<= threshold - max(NEAR_BAND_HYSTERESIS_C, GUARD_CUT_RESET_STEPS (1.5) * sensor step)`. Forces 0 %, integral unwound by back-calculation down to a floor (`_unwind_integral_during_guard_cut`), learning continues as a passive window (ON/A blocked `skip: guard cut`). Published in a cut (diagnostics only): error `guards.cut_error`, anticipation 0, `control.mode` `heating cut above the setpoint`. Not active in bootstrap or during a calibration pulse. Counter persisted (`guards_state`).
- Guard kick: HEAT only; in near band, `T < SP - near_band_below`, `on_percent < 0.99` -> forces a cycle restart; releases at threshold + 0.05.
- HVAC OFF (`_force_off_output`): output 0 and committed 0, resume hold dropped, `I:FREEZE(hvac_off)`, integral kept, `_last_calculate_time` cleared. On resume: raw setpoint first tick, learning paused 20 min; window/power-shedding resume starts `ResumeDeadtimeHold` (`smartpi/resume_hold.py`: I:HOLD over the active dead time, ended early when the residual error is below the recovery floor `2 * deadband`). Power shedding: output 0, regime PERTURBED. Missing indoor/target value: output 0 (or the held command of a bridged restart), `I:FREEZE(missing_sensor)`. Sensor staleness is VT's job, never judged here. VT safety mode: integral held (`vt_safety`).
- Restart (`smartpi/restart_bridge.py`): a stop <= `RESTART_BRIDGE_MAX_GAP_S` (600 s) with same mode, saved actuator state, no exclusion and a plausible first temperature is bridged (work in progress resumes); otherwise conservative handling (learning frozen one cycle, raw setpoint on first cycle).
- Inactivity: > 96 h wall-clock inactive -> PI memory purge (section 2).

## 10. Persistence map (`SmartPI.save_state`, version 2)

`est_state`, `dt_est_state`, `gov_state`, `ctl_state` (integral), `sp_mgr_state`, `lw_state`, `db_state`, `cal_state`, `gs_state`, `guards_state`, `ac_state`, `ff_source`/`ff_wall`, `tint_filter_state`, `learning_enabled`, `last_active_wall_ts`, `cycles_since_reset`, optional `hysteresis_output`, `restart`, and the learning-start keys `measure_events` (the record), `event_reading` (readings in progress and kept values; the older key `pulse_reading` still loads), `est_state` holds `starting_values`. States saved before these keys load. Storage plumbing in `state_store.py`.

## Invariants a change must not break

- Signs: HEAT `a > 0`, COOL `a < 0`, `b > 0`; `error` is positive when more power is needed in both modes; `k_ff = b/a` carries the sign; a sign-inconsistent persisted `a` resets only the mode-dependent channel (`ensure_hvac_mode`), `b` is kept. A mode change sets the mode-dependent part of the outgoing mode aside and takes back the one set aside for the incoming mode, a blank start without one: the `a` channel of `ABEstimator` (a, measures and observations, filtered history, counts, drift state, standing starting `a`; the measures follow the b of today), the whole `DeadTimeEstimator` learned state (its heat/cool slots swap meaning with the mode), the episodes of `PowerSteps`; `b` and the PI state are shared or reset as before. The set-aside part is the `mode_stash` key of `est_state`, `dt_est_state` and `lw_state.power_steps`, present only after a mode change (an older state loads without it); a learning reset clears both modes.
- Ranges: `u_*` in [0,1]; `Kp` in [0.10, 5.0], `Ki` in [0.001, 0.05]; `|I| <= 2/Ki`; `a`, `b` within their clamps; `u_ff*` clamped to [0,1].
- Back-calculation moves the integral toward zero only and never across it (FF absorption, `absorb_feedforward_step`, is the one explicit exception).
- Anti-windup excludes rate limit and min-activation timing; HEAT and COOL runs mirror each other exactly (tested trace equality).
- Bumpless: Ki change rescales `I`; FF step is absorbed into `I`; setpoint change never resets the integral; OFF keeps the integral (only > 96 h inactivity purges it).
- Optional features are bit-identical to the reference while silent (no published room model, no learned emitter lag, option off): same commands, same learning; additions must not perturb `u_cmd` until they publish.
- Learning uses raw temperatures for slopes, the committed (not requested) power, and never publishes on a window contaminated by setpoint transients, guard cut, dead-time overlap or governance freeze.
- Integral time is bounded `Ti <= 4*(lambda + L)` and `Ti <= tau`; deadband entry freezes without a bumpless jump.
- Diagnostics are read-only snapshots (`build_published_diagnostics`); the `live` schema is pinned by a schema test, extend it deliberately.
